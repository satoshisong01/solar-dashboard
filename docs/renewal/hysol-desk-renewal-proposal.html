현재 코드 진단

왜 크게 바꿔야 하나

지금 구조는 AI 분석의 토대가 되는 "쌓이는 원시데이터"와 정반대로 움직입니다.

브라우저가 데이터를 만든다대시보드 탭이 열려 있을 때만 30분마다 가짜 IoT 값을 저장합니다. 탭이 여럿이면 중복되고, 아무도 안 열면 비고, 밤에도 발전합니다.
원시데이터를 매일 지운다크론이 24시간 지난 로그를 삭제합니다. "8시간 → 7시간 30분" 같은 변화는 몇 달치 이력이 있어야 보입니다.
분석이 고정값이다고장유형 [12,5,8,3,2], SMP=160, "▲2.1% 전년 대비", 설치일 2023-01-15가 코드에 박혀 있습니다.
태양광 전용 평면 구조사이트 → 설비 → 부품 계층이 없어 수소 설비나 부품 단위 데이터를 넣을 곳이 없습니다.
보안인증 없음, 인증 없는 쓰기 API, RDS TLS 검증 끔, 지도 마커 XSS, 그리고 Next 16.1.1의 critical 취약점(npm audit 확인, 16.3.5에서 해결).

계약 없이 받는 수집 원장

모든 입력은 서명된 봉투 하나로 들어오고 원본은 그대로 보존됩니다. 모르는 태그도 거부하지 않고 인박스에 쌓았다가, 매핑하는 순간 원본을 재처리해 과거까지 채웁니다.

같은 조건 비교 엔진

원시 시계열을 충전 세션·정상운전 구간 같은 에피소드로 자르고, 전류·온도·부하 조건이 같은 기준선과 비교해 효과 크기와 95% 신뢰구간으로 판정합니다.

코칭 폐루프

발견사항 → 분석 데스크에서 근거·원인 판별 → 코칭 리포트 → 현장 조치 기록 → 조치 전후를 같은 조건으로 비교해 효과가 있었는지 수치로 닫습니다.

안전 레인 분리 — 수소 누출·ESD·화재·셀 한계 이벤트는 분석을 거치지 않고 즉시 고정 표시. 콘솔은 PLC 인터록을 대체하지 않으며, 통신이 끊기면 "안전 데이터 불확실"을 띄웁니다.
LLM은 문장만 교체 — 무엇을 말할지(수치·판정·우선순위)는 결정적 엔진이 정하고, 지금은 규칙 템플릿이 문장을 씁니다. 나중에 LLM을 붙여도 숫자는 못 바꿉니다.

파이프라인 따라가기

"8시간 걸리던 충전이 7시간 30분"을 잡는 과정

같은 50 A로 0→100% 충전 시간이 줄었다면 담기는 용량이 줄었다는 신호입니다. 콘솔은 이것을 이렇게 처리합니다. (표본 수·CI는 예시)

  1. 원시랙별 전류·전압·SOC·셀 전압 max/min·셀 온도를 10~60초 주기로 수집, 5분 배치 전송om.measurement
  2. 에피소드전류 > +0.02C 2분 이상이면 충전 시작, 5분 휴지면 종료. 사전 휴지·CV 종료 여부 태깅ess.charge
  3. 특징누적 Ah, 평균 C-rate, 셀 평균온도, CC 구간 Ah, CV 시간, 시작 SOC(휴지 OCV 기준)capacity_ah
  4. 같은 조건 비교준공 초기 20세션 기준선 vs 최근 30일을 C-rate 0.05C × 셀온도 5 °C 구간으로 짝지어 비교, 부트스트랩 95% CI400 → 375 Ah · −6.25%
  5. 원인 판별CC Ah 감소·CV 시간 증가로 용량 감소와 내부저항 증가를 구분. SOC 상한 설정 변경·저온·BMS 재보정 여부 확인원인 후보 순위
  6. 발견사항심각도 3, 신뢰도 0.8. 같은 문제는 매일 새로 만들지 않고 한 건에 누적. 근거 스냅샷 첨부ess.capacity_fade@1
  7. 리포트 문장"같은 조건 충전 18회 비교: 유효용량 400 Ah → 375 Ah(−6.3%), 50 A 기준 충전시간 약 8h 0m → 7h 30m" + 권고 조치 + 인용templateComposer@1
  8. 조치·검증"셀 밸런싱 + 기준 조건 용량시험" 기록 → 안정화 7일 후 전후 30일을 같은 구간으로 재비교improved / no_change

판정은 시간이 아니라 Ah(유효용량)로 합니다. 시간은 충전 전류·시작 SOC 차이와 BMS 재보정에 쉽게 흔들리기 때문입니다. 리포트에는 현장이 익숙한 "기준 전류 환산 시간"을 함께 적습니다.

태양광 연계 ESS는 저 SOC → 만충 세션이 드묾표본 부족은 "판단 불가"로 명시, 상단(CV 종료) 앵커·CC 구간 Ah 보조 지표, 정기 용량시험 입력
현장 게이트웨이가 서명·HTTPS 푸시를 못 함벤더 API·CSV 어댑터나 엣지 릴레이가 같은 봉투로 변환. 파일럿에서 확인
RDS 저장공간 급증셀 단위는 게이트웨이에서 통계로 축약, 원시 6개월 파티션 삭제, 장기 비교는 에피소드·롤업
콘솔을 안전설비로 오인안전 레인 분리, "법정 안전설비·PLC 인터록을 대체하지 않음" 고정 문구, 통신 두절 시 불확실 표시

P4 전까지 기본값으로 진행

운영 전환 전에 확인할 것

  1. 기존 RDS PostgreSQL 버전·리전·퍼블릭 접근 여부
  2. Vercel 요금제(Pro 전환 가능 여부)
  3. 사이트 데이터 실제 경로(게이트웨이 / SCADA·RTU / 벤더 클라우드 / CSV)와 포인트 수
  4. PV 경사면 일사계·모듈온도 센서, 출력제어 신호 수집 가능 여부
  5. 수소 설비 사양(전해조 방식, 저장 압력·용적, 연료전지 제조사 데이터)
  6. 원시 보존기간(기본 6개월)과 S3 아카이브 허용 여부
  7. 정비 이력 보관 위치(CMMS / 엑셀 / 없음)
  8. 코칭 리포트 수신자·주기·전달 방식
  9. 관리자 수와 2FA·IP 제한·사내 SSO 필요 여부
  10. 기존 solar_* 테이블 이관·백업 후 삭제 여부
  11. 향후 LLM에 운영 데이터 전송 가능 여부
